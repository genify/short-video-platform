## 2. 逐文件结论

### 2.1 `marketing/data/share_scripts.md` — 判定：**需改**（3 处 + 机器漏检 1 项）

**审什么**：渠道 2 分享话术 3 版，零数字零承诺；「可删减不可改写」的边界是否清楚。

**结论 A（机器漏检 · **需改**）—— 竞品对照**

- 原文（§2 社群版）：
  > 规则在开放前公开，每条内容都带一行可读的推荐理由——**这点比我用过的平台都清楚**。
- 问题：该句以「比我用过的平台都清楚」对同类平台作**比较性贬损**。同文件 §5 自己写明「**一切竞品对照与攻击性表述**：见 HB-14、HB-02、HB-03、HB-10」——即本文件**自定的禁用清单**已禁止该表述，但正文里有。§5.4-3「不比较推荐算法精度、内容池规模、变现成熟度」与 §5.4-4「不得把『未找到公开来源』表述为对手不透明的事实指控」同向。
- 为何机器漏掉：HB-14 正则为 `暗箱|黑箱|他们不给|对手不公开|对手不透明`，不匹配「比我用过的平台都清楚」。**这是词表语义盲区，不是豁免。**
- 建议改法（三选一，均不改写其余文案）：
  1. **删除**该从句，保留「规则在开放前公开，每条内容都带一行可读的推荐理由。」
  2. 改为**自我陈述**：把「比我用过的平台都清楚」换成「这一点我能自己核对」（主语回到自己，不涉对手）。
  3. 若确要保留一点对照意味，必须走 §5.0 来源纪律（A/B 级来源 + 注明出处），并**一次性登记到 §5 的允许清单**；否则维持删除。

**结论 B（**需改**）——「可删减不可改写」的边界不清楚**

- 原文（§0 使用前三条硬门 第 2 条）：
  > **话术不得改写**：可删减，不得新增任何数字或承诺（含「保证」「一定」「包」类词）。
- 问题：本条只写「不得新增」，未写「**哪些句子不可删**」。§1/§2/§3 三版话术中，**承载合规与伦理功能的句子**（「不用注册就能看」「我用的是邀请名额」「如果点不开，回我一句」）与**可自由删减的宣传句**混在一起，创作者删掉前者后，话术将失去「不强制注册」与「邀请制」的口径锚点，而责任落在创作者身上。
- 建议改法：在 §0 第 2 条下补一行「**以下句子不可删**（其余可删）：『不用注册就能看/不用注册也不用下载』『邀请名额』『我是创作者身份相关句』」，并把三版话术里对应句子加注 `〈不可删〉`。

**结论 C（**需改**）—— 承诺等级表述与收紧裁定不一致**

- 原文（文件头纪律 + §0 第 2 条）：
  > 纪律：**本文件所有版本都不得出现任何未兑现数字**。
  > 不得新增任何数字或承诺（含「保证」「一定」「包」类词）。
- 问题：`pre_t0` 收紧裁定禁止的是**一切结果承诺（含无数字）**，不限于「未兑现数字」，也不限于「保证/一定/包」三个词。对照 `creator_outreach.md` §3（已正确写明「任何效果承诺，即使没有数字（如『保证有人看』类表述），一律禁止」），**同一类禁令在两份物料里强度不同**（详见 §4.1）。
- 建议改法：把文件头纪律改为与 `creator_outreach.md` §3 同款措辞：「本文件在 `pre_t0` 相位下不得出现**任何数字与任何结果承诺**（含无数字表述，如『有人看』『被看见』）；词例仅作提示，不作为判断边界。」

**结论 D（建议 · 不阻断）—— 单条无履约约束的承诺句**

- 原文（§3 短视频平台私信版）：
  > 如果点不开，回我一句，我直接发你视频。
- 问题：这是对观众的**一对一履约承诺**，但无留痕、无边界（发在哪、多久内）。属轻微未兑现暗示（不构成对外承诺数字，故不阻断）。
- 建议改法：改为「如果点不开，回我一句，我把视频发在这里的评论区」——把「一个人对一个人」的低概率履约改为可留痕的公开动作。

**结论 E（通过）**：三版话术均无数字；「规则先公开」「推荐理由可回读」「不用注册」「邀请制」均为 §0.1 允许的**机制类表述**；「一次只发一跳」「同一社群 7 天内 ≤ 2 条」纪律清晰；§5 以规则编号引用禁用项（不复述原文）符合「不得在物料里逐条豁免」的纪律。

### 2.2 `marketing/data/creator_outreach.md` — 判定：**通过**（建议 2 项）

**审什么**：1v1 招募话术（T0 前版）。

**通过理由**
1. **零数字、零结果承诺**：三步触达全程无数字；第 3 步「③ 现在还不能承诺任何数字，等规则开放我会把规则原文发你，你再决定要不要首发。」把「不给数字」写成了**主动披露**，是本次审查中处理得最干净的一份。
2. **伦理红线三项齐备**（§2 表 + 第 3 步正文）：收集目的（只用于内测邀请）/ 保留期（90 天，到期删除）/ 退出方式（回复「退出」即删除）——与 `lexicon.json` RT-01/RT-02/RT-03 一一对应，且**写在要发给创作者的话术正文里**（而非只在文档里声明），这点优于其他物料。
3. **§3 禁止清单是 7 份物料里唯一完整覆盖「无数字结果承诺」的**（明确列出 TG-05、TG-06）。
4. **§4 异议处理**每行都写「不得答/不得给」，边界清楚；「有补贴吗」→「没有现金补贴，也没有买量」正面否定了 HB-15。

**建议 1（措辞风险 · 不改不影响投放）**

- 原文（§4）：
  > 我们不比算法精度。差别在：我们把新创作者首发的**曝光下限**写成产品约束，而且你会看到每条内容的推荐理由。
- 问题：「曝光下限」是**下限 = 结果的定量概念**，与 `copy_pack.json` 的 pre_t0 官方措辞「曝光规则 → 硬约束」不同等级；在 T0 前使用，容易被对话方理解为「存在一个保底曝光」，而 §0.3 明确「保底曝光 500」已删除且数字承诺 T0 才能给。
- 建议改法：把「首发的曝光下限写成产品约束」改为与文案包同口径的「**把首发的曝光规则写成产品里的一条硬约束**（具体数值规则开放时一并公开）」。四份物料的机制措辞统一建议见 §4.2。

**建议 2（轻微）**

- 原文（§5 记录要求）：「邀请发出时间 | 用于『7 天内首发率 ≥ 50%』的阶段判据」
- 说明：此处「7 天内首发率 ≥ 50%」是**内部判据**（PRO-4 A7），出现在 T0 前的话术文档中不构成对外承诺，**判定为合规**；仅建议加注「（内部判据，不得对外引用）」，防止被 1v1 话术执行人顺口带出。同类加注建议亦见 §2.3 结论 F。

### 2.3 `marketing/data/community_scripts.md` — 判定：**需改**（3 处 + 机器漏检 2 项）

**审什么**：渠道 3 社群清单 + 3 个创作者身份脚本 + 异议处理表；重点为 `⟨真实曝光数⟩` 占位纪律是否写死。

**结论 A（**需改**）—— 占位纪律「写死了，但强度不一致」**

- 文件头纪律（写死了）：
  > 纪律：**只发真实数字**；未拿到真实曝光数据前，一条都不发。
- 三处占位符的写法并不一致：
  | 位置 | 占位原文 | 是否内联「不得发布」约束 |
  |---|---|---|
  | 脚本 A 评论区 | `【实证】首发 24h 曝光：⟨真实曝光数，未拿到数据前不得发布⟩` | **是** |
  | 脚本 B 评论区 | `【实测数据】原平台 24h：⟨真实数字⟩；内测社区 24h：⟨真实数字⟩` / `样本只有 N=⟨真实条数⟩ 条` | **否** |
  | 脚本 C 评论区 | `【实证】三条 24h 曝光：⟨真实数字 ×3⟩` / `⟨主页/专属链接⟩` | **否** |
- 问题：纪律只在文件头与脚本 A 中显式，脚本 B/C 的占位符本身**可被原样复制发送**而不触发任何警示；脚本 B 的占位符甚至没有「24h」这一时间窗限定（`⟨真实数字⟩` 无口径），与 §1 硬门 1「必须包含一次『真实曝光数 + 推荐理由』的展示」存在口径漂移风险。
- 建议改法：① 三处占位统一为脚本 A 的完整形式（`⟨真实曝光数（24h），未拿到数据前不得发布⟩`）；② 脚本 B 的 `⟨真实数字⟩` 补口径为 `⟨原平台 24h 真实曝光数⟩` / `⟨内测社区 24h 真实曝光数⟩`；③ 文件头纪律补一句「占位符一旦被替换为数字，须同时满足：有真实数据、有推荐理由原文、有来源参数链接，三者缺一不发」。

**结论 B（机器漏检 · **需改**）—— 能力表述超出已实现范围**

- 原文（脚本 A 正文）：
  > ① 每条内容都写了一行推荐理由（**我能看到它被推给谁、为什么**）；
- 问题：实现侧 `server/recommend.py` 的 `_reason_for()` 只输出「**〈某种子主导〉（召回路径：〈路径名〉）**」——例如「标签兴趣匹配主导（召回路径：标签匹配/协同过滤）」。**该字符串不含任何受众信息**（「被推给谁」在实现中不存在），也正因为如此 PRD 侧对文案的要求是「审查文案不泄露权重与风控」（`docs/04-mvp-prd.md` D11 / FR-2.6.e）。要求创作者照抄的脚本里出现「我能看到它被推给谁」，是**未兑现暗示**（对观众的机制描述超出实现）。
- 为何机器漏掉：词表无对应规则；HB-13 的 `reason` 文本覆盖「未上线能力」，但 pattern 只枚举变现类词（打赏/带货/电商闭环/会员订阅/商单/接单）。
- 建议改法：删除「被推给谁」，保留可兑现部分——「① 每条内容都写了一行推荐理由，我能看到它为什么被推。」（或按 PRO-7 最终实现口径回填后再写）。

**结论 C（机器漏检 · **需改**）—— 创作者个人事实被写死**

- 原文（脚本 A / 脚本 C 正文）：
  > 我做了三年家常菜，最烦的不是没流量，是不知道为什么没流量。
  > 帮一家开了 12 年的面馆拍了三条。老板只问了一个问题：「拍了没人看，不是白搭吗」。
- 问题：「三年家常菜」「开了 12 年的面馆」「三条」是**具体个人事实**。脚本以创作者**第一人称**发布，若由事实不符的创作者照抄（20 名种子创作者并非都做了三年家常菜、也并非都拍过 12 年老店），即构成**虚假陈述**——这是比词表违规更严重的风险（受众可核对、平台可判定）。
- 建议改法：在 §2 标题下加一行使用约束：「**本组脚本仅限事实相符的创作者使用**；`{垂类}`、`{年限}`、`{店龄}`、`{条数}` 等个人事实须替换为创作者自己的真实情况，不得照抄本文示例值」；并把示例值改为显式占位（`我做了〈真实年限〉年家常菜`、`帮一家开了〈真实店龄〉年的〈店名/品类〉拍了〈真实条数〉条`）。

**结论 D（通过）**：§1 社群清单的 5 条准入标准与「发帖前三道硬门」（有真实数据 / 链接合规 / 身份披露）边界清楚；§3 异议处理表把「又是广告」「能涨多少粉」「跟我们平台比怎么样」逐条给了「不得回复」；脚本 B 主动写明「样本只有 N=…，不构成任何效果保证」与「结论我先不放（样本太小，放了就是耍流氓）」——**这是全部物料中对「不构成效果承诺」表述最充分的一处**。

**结论 E（建议 · 不阻断）—— 内部判据出现在对外脚本文件内**

- 原文（§4 归因与回执）：「社群来源用户 D1 | 带社群来源参数的新用户次日留存 ≥ 25%」；「每垂类月参与创作者 | ≥ 50 名」；「话题内容占比 | ≥ 20%」。
- 说明：均为内部 KPI，非对外文案，判定合规；仅建议表头加注「（内部口径，不得对外引用）」（同 §2.2 建议 2）。

### 2.5 `marketing/landing/copy_pack.json` — 判定：**需改**（4 处 + 机器漏检 3 项）

**审什么**：文案包两臂（pre_t0 / t0）× 3 变体 × 招募/分享 + 9 个命名候选。

**结论 A（机器漏检 · **需改**）—— 命名候选 A1/A2/A3 的 slogan 属无数字结果承诺**

- 顺带（建议）：`compliance` 侧的覆盖缺口建议由 PRO-10 一并处置（把 `naming_candidates` 纳入扫描，或明确登记为「非投放文案」并在 §3 说明），否则同类 slogan 下次仍会静默通过。

**结论 B（机器漏检 · **需改**）—— 招募 V3 `pre_t0` 臂宣传未上线能力**

- 原文（`assets.recruit.variants.V3.pre_t0`）：

**结论 C（机器漏检 · **需改**）—— 分享 V2 `pre_t0` 臂承诺「现在就能看到」，装置无兑现位**

- 原文（`assets.share.variants.V2.pre_t0`）：

**结论 D（**需改**）—— `rules[2]` 的文字与包内数据不符（表述歧义）**

- 原文（顶层 `rules` 第 3 条）：
  > 两臂的 h1/动机维度必须一致（V1 被看见 / V2 规则透明 / V3 省时间），只有「兑现表述」不同，否则分流结果不可比。

**结论 D（**需改**）—— §4.2 表内一处自评为不准确的表述**

**结论 A（**需改**）—— 卡面结语与卡片正文自相矛盾**

- 原文（§4 卡面文案，第 4 段）：
  > 这三条数字是我们对外承诺的全部内容；
- 对照：§1 标题写的是「对外承诺（**只允许这 3 个数字 + 2 条非数字承诺**）」，卡面正文列了 **5 条**（第 4 条推荐理由可见、第 5 条分成规则先公开后结算均为承诺）；§5.0（`docs/05` §5.0）亦写「另有『推荐理由可见』与『规则先公开后结算』」。
- 问题：结语把「三个数字 = 全部承诺」写成等式，与同一张卡片上并列的 4/5 条（非数字承诺）冲突。这不是措辞偏好问题——**它会影响兑现纪律**：创作者读到「全部内容就是三个数字」，在推荐理由或「先公开后结算」未被兑现时，会（且应当）认为自己没被承诺过。
