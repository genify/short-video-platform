# 命名测试投放说明（命名测试方案配套物料）

> 依据：`docs/05-gtm-plan.md` §4.2 决策规则（分两批测、不叠加分流维度）；PRO-10 交付物 3。
> 纪律：**第一批与第二批都在 T0 前的假门流量池内跑**，两批共用同一落地页服务，但**不混算**。
> 纪律（承诺）：本文件覆盖的**候选文案**同样受 `pre_t0` 收紧裁定约束——**不得含任何数字，也不得含任何结果承诺**（含无数字表述）。候选文案按臂存放于 `marketing/landing/copy_pack.json` 的 `naming_candidates`，并已纳入合规扫描。
> 合规：本文件按 pre_t0 相位扫描（禁用项按编号引用）。
> 本轮处置：PRO-13（承接 PRO-12 人工终审 §2.4 的 3 处需改 + §3.1 L-1 + §3.2 L-8）。

## 1. 两批设计（不得合并成一批）

| 批 | 测什么 | 分流维度 | 每格样本 | 主判据 | 判定规则 |
|---|---|---|---|---|---|
| 第一批 | **价值主张**：V1 被看见 / V2 规则透明 / V3 省时间 | 3 格（访客哈希等分） | 每格 100–167（合计 300–500） | `form_submit`（留资转化率） | 留资转化率 ≥ 8%，且 V1 − max(V2,V3) ≥ 3pp |
| 第二批 | **命名**：3 个方向 × 3 个候选 = 9 个候选，**分 3 个子批**（每次只上 3 个候选） | 每子批 3 格（`naming` 参数，见 §3） | 每子批合计 ≥ 300 | `cta_click` | 同一子批内 cta_click 差异 ≥ 3pp |

**为什么必须分批**：9 个候选一次分流会把每格压到 33–56 人，在 80% 功效下最小可检测差异达 23–31pp，等于没有判定能力。计算见 `marketing/reports/pro10-power-and-mde.md`。

**第二批的两个前置条件（PRO-13 新增）**：
1. **渲染路径必须先可用**：被测者必须真的看到候选名/Slogan，否则 `cta_click` 差异无法归因。PRO-13 已实现（见 §3）；未部署前不得开跑第二批。
2. **相位口径**：`pre_t0` 只展示各候选的 `pre_t0` 臂文案（机制类替代句，或 `slogan` 为 `null` 时仅展示名称）；结果承诺型/情感型 Slogan 存在 `t0` 臂，T0 前**不得展示**。

## 2. 候选清单（9 个）

> 下表「Slogan」列给出的是 **`pre_t0` 相位唯一可展示的句子**（T0 前用它投放）。

| 方向 | 候选 | pre_t0 可展示 Slogan | 备注 |
|---|---|---|---|
| A 结果承诺型（命名语义） | 光见 / 见字 / 首见 | 规则写出来，你自己核对 / 每条理由都写出来 / 首发走独立路由 | 命名语义与核心动机直连；**该方向的结果承诺型 Slogan 在 `t0` 臂，T0 前不得展示**；须先做商标与域名初筛 |
| B 培育隐喻型 | 苗圃 / 引路 / 拾光 | 先育苗，再谈赛道 / 路线都写在明处 / （无：仅展示名称） | 攻击性最低，但需一句 Slogan 承接「确定性」 |
| C 垂类身份型 | 食集 / 城集 / 号集 | 家常菜与探店，一个集子 / 你所在城市的小店与市集 / 创作者的集子 | 社群辨识度高，但天花板低、跨品类受阻 |

**分 3 个子批的顺序**：子批 1 = A（A1/A2/A3）→ 子批 2 = B（B1/B2/B3）→ 子批 3 = C（C1/C2/C3）。每个子批跑满 300 访客再开下一个，**不并行**。

**子批 1 的前置条件（PRO-13 新增）**：A 方向自身标注「须先做商标与域名初筛」，而本单不产出最终命名（超出授权）。因此：**子批 1 开跑前，A 方向须完成商标与域名初筛并留档；未完成则顺延至子批 3，B/C 先跑**（排期与前置条件自洽）。

## 3. 物料与分流实现

| 物料 | 位置 | 说明 |
|---|---|---|
| 分流统计（`page_view` / `cta_click` / `form_submit`） | `marketing/landing/app.py` | 访客哈希等分、粘性 cookie、事件入库 |
| 文案与候选 | `marketing/landing/copy_pack.json` | 命名候选在 `naming_candidates`；**每个候选的文案按臂（`pre_t0` / `t0`）存放**，且整个节点已纳入合规扫描 |
| 候选渲染 | `marketing/landing/app.py` → `Application.naming_candidate()` + `render_recruit(..., naming=...)` | 请求带 `naming=A1`（等已登记 id）时，页面在标题上方渲染「候选名 + 当前臂 Slogan」，页脚显示「候选=A1」便于人工核对；未登记的 id 一律忽略 |
| 分流取数 | `GET /api/stats` 的 `naming` 段 | 按事件里的 `naming` 字段（A1/B2/C3…）聚合 `cta_click`；页面的 `page_view`、脚本上报的 `cta_click`、`/api/lead` 三处都会带 `naming` |
| 合规门禁 | `marketing/landing/compliance.py` | 文案（含候选与界面文案）含禁用表述时服务拒绝启动 |

**批次二的投放链接写法**（在招募链接后追加，顺序固定）：

```
{landing}/?utm_source={platform}&utm_medium=creator_recruit&utm_campaign=pro_launch_p1&utm_content={code}&ref={code}&naming={A1|B2|C3…}
```

同一子批只允许出现该子批的 3 个 id；**子批之间不得混跑**。

5. [ ] 判定前先看 `marketing/reports/pro10-power-and-mde.md`：样本未达 MDE 门槛时，只能写「方向性结论」。
6. [ ] 子批 1（A 方向）开跑前已完成商标与域名初筛并留档；否则先跑 B/C。

## 5. 预注册判定规则（先写死，后看数）

| 情形 | 判定 | 后续动作 |
|---|---|---|
| 留资 ≥ 8% 且 V1 − max(V2,V3) ≥ 3pp，且每格样本 ≥ 100 | 「确定性」为主驱动 | 定位叙事维持 V1 |
| 留资 ≥ 8% 但差值 < 3pp | 「确定性」非主驱动 | 定位叙事改为「规则/收益透明」（PRO-8 §3.2 停止条件 ①） |
| 留资 < 8% | 招募叙事整体不成立 | 停止扩投放，回炉文案与渠道选择 |
| 样本已达 500 但 MDE 仍 > 3pp | **不得宣称 3pp 判定** | 只记方向性结论，并把该结论标注为低功效 |
| 命名子批内 3 个候选差异 < 3pp | 该方向内无显著差异 | 记录「无差异」，不得凭偏好选名 |

## 6. 边界（本单不做）

- 本单**不产出最终命名**：商标与域名检索属合规前置，超出授权（PRO-8 §4.2 原文）。
- 不买量、不买创作者、不做站内关系链；命名测试不得使用收益类话术（HB-12、HB-13）。
