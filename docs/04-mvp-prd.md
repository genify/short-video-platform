# 短视频平台 MVP · 产品需求文档（PRD）

> 范围：视频上传 + 推荐流（需求明文指定的两项核心功能）
> 版本：v1.0（首个可运行版本，对应 `server/` 实现）
> 前置输入：`01-competitive-analysis.md`、`02-user-research-personas.md`、`03-recommendation-design.md`

---

## 一、产品目标与边界

### 1.1 一句话定位

**面向垂直品类创作者的短视频平台：让新创作者的第一条视频就能拿到确定的曝光。**

这个定位直接来自调研结论——存量竞争下（用户渗透率 95.4%，年增速 0.8%），胜负手在**供给侧的确定性**，而不是再来一个更聪明的信息流。

### 1.2 本 MVP 要证明的三个假设

| # | 假设 | 验证方式 | 护栏指标 |
|---|---|---|---|
| H1 | 新创作者首发视频能获得非零且稳定的曝光 | 首发 24h 曝光量 P10 ≥ 50 | 举报率 < 0.5% |
| H2 | 标签匹配驱动的推荐流在冷启动期即可产生个性化 | 冷启动用户前 10 条中兴趣标签命中率 ≥ 60% | 跳过率 < 40% |
| H3 | 多样性重排不会显著损伤短期消费 | MMR 组人均观看时长 ≥ 纯相关性组 × 0.95 | 次日留存不降 |

### 1.3 明确不做（Non-Goals）

- ❌ 直播、连麦、IM 私信
- ❌ 电商、打赏、支付
- ❌ 视频编辑（剪辑/滤镜/特效）
- ❌ DNN 排序模型（无行为数据前是负收益）
- ❌ 多端（Web 端 API 优先，移动端后续）

## 三、功能规格

### 3.1 视频上传（P0）

**接口**：`POST /api/videos`，`multipart/form-data`

| 字段 | 必填 | 说明 |
|---|---|---|
| `file` | ✅ | 视频文件，支持 mp4 / mov / webm / mkv |
| `creator_id` | ✅ | 创作者 UUID，必须已注册 |
| `caption` | ❌ | 文案，≤500 字，支持 `#话题` 自动抽标签 |
| `tags` | ❌ | 显式标签，逗号/空格分隔，与 `#话题` 合并去重 |

**校验矩阵（服务端强制，不信任客户端）**：

| 校验项 | 规则 | 失败响应 |
|---|---|---|
| 扩展名 | 属于 `.mp4/.mov/.webm/.mkv` | 400 `unsupported_extension` |
| MIME | 属于白名单 4 种 | 400 `unsupported_mime` |
| 请求体大小 | ≤ 200MB | 413 `payload_too_large` |
| 文件大小 | > 0 | 400 `empty_file` |
| 时长 | 1s ~ 180s | 400 `duration_too_long` / `duration_too_short` |
| 分辨率 | 高度 ≥ 240px | 400 `resolution_too_low` |
| 可解码性 | ffprobe 能解析 | 400 `unprobeable_media` |
| 重复 | sha256 未出现过 | 409 `duplicate_video` |

**设计要点：元数据以 ffprobe 为准。** 时长与分辨率一律服务端探测，客户端无法伪造。这是风控基本要求——否则用 3 秒 MP4 即可冒充 3 分钟视频骗取时长推荐权重。

**存储**：按 `var/media/YYYY/MM/<video_id>.<ext>` 分桶，避免单目录文件数爆炸。

**标签抽取**：正则 `#([^\s#，,。、；;]{1,24})` 从文案提取，合并显式 `tags`，规范化（小写、去重、限 8 个）。

### 3.2 推荐流（P0）

**接口**：`GET /api/feed?user_id=<uuid>&size=10[&seed=<int>]`

**流水线（三段式）**：

```
① 多路召回                                  ② 线性加权排序            ③ MMR 重排
┌──────────────────────────┐              ┌──────────────────┐    ┌──────────────┐
│ cf        item-item 协同  │ 30% ─┐       │ S = 0.45·Aff     │    │ MMR λ=0.7    │
│ follow    关注创作者      │ 25% ─┤       │   + 0.20·Pop     │ →  │ 创作者打散   │
│ fresh     热门新鲜(HN衰减)│ 20% ─┼─配额→ │   + 0.15·Fresh   │    │ ε-greedy     │
│ tag       标签内容匹配    │ 15% ─┤       │   + 0.10·Social  │    │ 去重/已看过滤│
│ fallback  冷启动兜底      │ 10% ─┘       │   + 0.10·Qual    │    └──────────────┘
└──────────────────────────┘              └──────────────────┘
```

**特征定义**：

| 特征 | 定义 | 取值范围 |
|---|---|---|
| `Aff`（兴趣） | 用户标签画像与视频标签向量的余弦相似度；画像由行为价值加权（like 3 / share 5 / skip −2） | 0 ~ 1 |
| `Pop`（热度） | `log1p(互动总量) / log1p(全站最大互动量)`，对数压缩防头部垄断 | 0 ~ 1 |
| `Fresh`（新鲜） | `0.5 ^ (age_hours / 48)`，48 小时半衰期 | 0 ~ 1 |
| `Social`（社交） | 关注创作者=1.0；二跳社交=0.5；否则 0 | {0, 0.5, 1} |
| `Qual`（质量） | `0.6·min(1, 完播率/0.55) + 0.4·min(1, 点赞率/0.12)` | 0 ~ 1 |

**重排规则**：
1. **MMR**：`argmax[λ·Rel − (1−λ)·max Sim]`，λ=0.7，相似度用标签 Jaccard
2. **创作者打散**：单创作者一条 feed 内最多 2 条；若因此凑不满长度则放宽补位
3. **ε-greedy 探索**：10% 请求插入探索位（非冷启动用户）
4. **去重**：7 天内已互动视频不重复推荐

**响应含可解释字段**（运营归因用）：
```json
{
  "video_id": "...", "creator_id": "...", "tags": ["美食"],
  "score": 0.4821,
  "features": {"aff": 0.71, "pop": 0.33, "fresh": 0.86, "social": 0.0, "qual": 0.45},
  "recall_routes": ["cf", "tag"],
  "reason": "标签兴趣匹配主导（召回路径：标签匹配/协同过滤）",
  "is_exploration": false
}
```

### 3.3 冷启动（P0）

| 场景 | 判定 | 策略 |
|---|---|---|
| 新用户 | 历史行为 < 3 条 | 放大兜底池至 50+ 候选；以分垂类热门 + 标签多样性（MMR 从全库采样）为主；不启用探索位 |
| 新视频 | 无任何互动 | 由 `tag` / `fresh` 路由承接可获得初始曝光；无标签则进 `fallback` |
| 新品类 | 标签无邻居 | MMR 多样性采样，避免长尾内容永久零曝光 |

### 3.4 互动埋点（P0）

`POST /api/engagements`，`kind ∈ {view, complete, like, share, skip, comment, follow}`

- 反规范化计数器（`video_stats`）同步更新，避免推荐打分时聚合扫描
- `kind=follow` 时自动建立关注边（创作者 = 视频作者）
- `watch_ms` 仅用于离线分析，不参与实时打分（避免打分成热点写）

## 四、非功能需求

| 类别 | 要求 | 当前实现 |
|---|---|---|
| 依赖 | 零第三方包 | ✅ 纯标准库 |
| 内存 | 上传 200MB 时驻留 ≤ 64KB | ✅ 流式 boundary 扫描 |
| 并发 | 读并发无锁，写串行化 | ✅ 线程级连接 + 单写锁 + WAL |
| 可测试性 | 核心逻辑与 HTTP 解耦 | ✅ `Application` 可直接单测 |
| 可解释性 | 每条推荐可归因 | ✅ `features` + `reason` |
| 可调参 | 权重改配置不改代码 | ✅ `server/config.py` |
| 鉴权 | — | ⚠️ 未实现（MVP 内网假设，上线前必须补） |
| 限流 | — | ⚠️ 未实现 |

## 六、已知限制与后续迭代

| 优先级 | 事项 | 说明 |
|---|---|---|
| P0 | 推荐权重离线校准 | 当前 `0.45/0.20/0.15/0.10/0.10` 为行业经验初值，必须用真实日志网格搜索 |
| P0 | API 鉴权 + 限流 | MVP 假设内网，上线前必须补齐 |
| P1 | 存储引擎迁移 | SQLite 单写锁是并发天花板，迁 PostgreSQL |
| P1 | 自动打标 | 当前依赖文案 `#话题`，覆盖率不足；应引入视频理解模型 |
| P1 | 护栏告警 | 举报率/跳过率/Gini 已可算但无阈值告警与自动回滚 |
| P2 | 多目标排序 | 单目标会诱发标题党，需融合完播/互动/关注多目标 |
| P2 | 实时特征 | 当前全部为请求时计算，热点场景需预计算与缓存 |
