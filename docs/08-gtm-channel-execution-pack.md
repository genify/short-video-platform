## 1. 渠道 2 落地包｜创作者自有渠道 + 站外分享回流

### 1.1 每名种子创作者的专属链接 + 二维码

**生成方式（离线、可复跑、幂等）**

```
python3 marketing/scripts/make_creator_links.py \
  --input marketing/data/seed_creators.csv \
  --outdir marketing/out \
  --landing-base <招募假门落地页基址> \
  --app-base <应用侧基址>
```

**实测输出（本次已生成）**：22 名创作者 / 22 条链接（正式 20 + 演示 2），`marketing/out/qr/` 下 svg + png 各 22 个；词表校验 15 条 hard_ban 规则全部通过。

**URL 规则（顺序固定，不得手改）**

| 用途 | 模板 |
|---|---|
| 招募（发给创作者本人） | `{landing}/?utm_source={platform}&utm_medium=creator_recruit&utm_campaign=pro_launch_p1&utm_content={code}&ref={code}` |
| 分享（创作者发给自己观众） | `{app}/s/{video_id}?utm_source={platform}&utm_medium=creator_share&utm_campaign=pro_launch_p1&utm_content={code}&ref={code}&v={variant}` |

示例（`c001` / douyin，占位基址）：

```
https://<landing>/?utm_source=douyin&utm_medium=creator_recruit&utm_campaign=pro_launch_p1&utm_content=c001&ref=c001
https://<app>/s/{video_id}?utm_source=douyin&utm_medium=creator_share&utm_campaign=pro_launch_p1&utm_content=c001&ref=c001&v={variant}
```

**纪律**：
1. 来源参数是 §0.3 #5（来源参数 + 归因落库）与循环边 `v`/`r` 的**唯一取数依据**；换成短链或去参数链接 → 该创作者贡献无法归因。
2. `utm_content`/`ref` 用 `creator_code`，与 `marketing/data/seed_creators.csv` 一一对应；编码规则 `^[a-z0-9]{4,16}$`。
3. 生成器内置 15 条 hard_ban 词表校验：台账文本或链接命中禁用表述 → **拒绝生成**（exit 1）。

**二维码实现与验证（可复核）**

| 项 | 内容 |
|---|---|
| 实现 | `marketing/scripts/qr.py`，纯 Python 标准库（无第三方依赖），字节模式 / 纠错等级 M / 版本 1–40 自适应 |
| 参考比对 | `marketing/tests/test_qr_reference.py` 用独立实现（`api.qrserver.com` 渲染的 PNG）逐格比对：**版本 6/8/13（dim 41/49/69）全部逐格相等** |
| 已知差异（不影响可用性） | 掩码选择：ISO/IEC 18004 允许编码器在 8 个掩码中自选，任一合法掩码解码结果相同。本实现按自己的罚分实现选掩码；实测中版本 13 与参考实现选到同一个掩码，版本 8 不同。**这是编码器自选项，不是缺陷** |
| 离线可用 | 生成链路完全离线；参考比对在无网络/无 PIL 时自动跳过（不 fail） |

### 1.2 统一分享话术模板（零未兑现数字）

## 3. 命名测试方案

### 3.1 两批设计（不合并、不叠加分流维度）

| 批 | 测什么 | 格数 | 样本 | 主判据 |
|---|---|---|---|---|
| 第一批 | 价值主张 V1/V2/V3 | 3 格 | 合计 300–500 访客 | `form_submit`（留资转化率 ≥ 8%，V1 − max(V2,V3) ≥ 3pp） |
| 第二批 | 命名 9 个候选，**分 3 个子批**（每子批 3 个） | 每子批 3 格 | 每子批合计 ≥ 300 | `cta_click` 差异 ≥ 3pp |

### 3.2 三个方向 × 各 3 个候选

| 方向 | 候选 | 适配与风险 |
|---|---|---|
| A 结果承诺型 | 光见 / 见字 / 首见 | 与核心承诺直连；须先做商标与域名初筛（重名风险最高） |
| B 培育隐喻型 | 苗圃 / 引路 / 拾光 | 攻击性最低；与「确定性」的联结需一句 Slogan 承接 |
| C 垂类身份型 | 食集 / 城集 / 号集 | 社群辨识度高；天花板低、跨品类扩张受阻 |

> 候选 id（A1…C3）已写入 `copy_pack.json` 的 `naming_candidates`；分流统计按事件里的 `naming` 字段聚合 `cta_click`。

### 3.3 样本量与最小可检测差异（**本单的关键发现**）

判据写的是「样本 300–500 访客、差异 ≥ 3pp」。先把 3pp 在 300–500 样本下是否可判定算清楚（`marketing/scripts/power_analysis.py`，两比例 z 检验、双侧 α=0.05、80% 功效、三臂等分）：

| 总访客 | 每臂 | 较弱臂基线 | 检测 3pp 的功效 | 80% 功效下 MDE | 判定 3pp 所需总样本 |
|---|---|---|---|---|---|
| 300 | 100 | 8% | 10.8% | **14.1pp** | 4,497 |
| 500 | 167 | 8% | 15.2% | **10.3pp** | 4,497（Bonferroni 修正 5,445） |
| 3,000 | 1,000 | 8% | 62.9% | 3.7pp | — |
| 4,500 | 1,500 | 8% | 80.0% | 3.0pp | — |

**结论（必须写进看板）**：
1. 300–500 访客时每臂仅 100–167 人，80% 功效下只能检测 **10–14pp** 的差异 → **不足以判定 3pp**。
2. 要判定 3pp，需约 **4,500** 名访客（若做 Bonferroni 修正则约 **5,445**）。
3. 因此本单把 300–500 访客的读数定位为**方向性判据**，正式判定按下表预注册规则执行；**不得**在低功效样本上宣称 3pp 结论。
4. 命名必须分批：9 个候选一批会把每臂压到 33–56 人，MDE 达 **23–31pp**，等于放弃判定能力（与 PRO-8 §4.2 一致）。

### 3.4 预注册判定规则（先写死，后看数）

| 情形 | 判定 | 动作 |
|---|---|---|
| 留资 ≥ 8% 且 V1 − max(V2,V3) ≥ 3pp 且每格 ≥ 100 | 「确定性」为主驱动 | 定位叙事维持 V1 |
| 留资 ≥ 8%，差值 < 3pp | 「确定性」非主驱动 | 定位改为「规则/收益透明」（PRO-8 §3.2 停止条件 ①） |
| 留资 < 8% | 招募叙事不成立 | 停止扩投，回炉文案与渠道 |
| 样本已达 500 而 MDE 仍 > 3pp | **不得宣称 3pp 判定** | 只记方向性结论并标注低功效 |
| 命名子批内差异 < 3pp | 该方向内无显著差异 | 记「无差异」，不得凭偏好选名 |
