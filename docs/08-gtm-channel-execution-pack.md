## 0. 执行口径与边界（先读）

### 0.1 相位（phase）是唯一开关

| 相位 | 触发 | 允许对外说 | 禁止 |
|---|---|---|---|
| `pre_t0` | 现在 → T0 前 | 机制类表述：规则先公开、推荐理由**回读位**（随功能开放后；见 §6.1 兑现位登记）、邀请制内测 | **一切结果承诺**（含无数字的；**board 裁定 3 已确认，PRO-25 轮**）；**一切数字**（曝光量、涨粉、收入、分成比例） |
| `t0` | T0 起（PRO-7 交付 + §0.3 八项前置全绿） | §3.5 白名单 3 个数字 + 推荐理由可见 + 先公开后结算 | 未兑现即停投；未上线能力；对手未公开来源的数字 |

- 代码层已经把这个开关做成**启动硬门**（三道，任一不过即拒绝启动）：
  ① **合规门禁**：`pre_t0` 相位下文案若含量化承诺，落地页服务**拒绝启动**（exit code 2）；扫描范围为 `copy_pack.json` 的 `assets.*` + `naming_candidates.*` + `ui.*`。
  ② **T0 前置校验**（本单新增，闭合 PRO-12 §5 D-3）：`--phase t0` 必须同时给 `--t0-evidence <T0 证据 JSON>`，且证据里「PRO-7 交付」与「§0.3 八项前置全绿」均为 true、并列出八项、写明采集日；否则**拒绝启动**（exit code 3）。
     **门禁的能力边界（PRO-14 R-6，必须一并读）**：它校验的是「**是否提交了结构完整的 T0 证据**」（两个 true + 八项条目 + 采集日非空），**不校验八项证据内容的真伪**；证据本身的真实性由证据留档 + 人工复核负责。
     `--phase t0` 的启动**须附 T0 证据并留痕，不得仅凭操作人判断**。模板：`marketing/data/t0_evidence.template.json`（默认全 `false`，刻意 fail-closed）。
  ③ **界面文案完整性**：`ui.*` 必需键缺失即拒绝启动（exit code 4），避免页面出现未替换的占位符。

## 1. 渠道 2 落地包｜创作者自有渠道 + 站外分享回流

### 1.1 每名种子创作者的专属链接 + 二维码

**生成方式（离线、可复跑、幂等）**

```
python3 marketing/scripts/make_creator_links.py \
  --input marketing/data/seed_creators.csv \
  --outdir marketing/out \
  --landing-base <招募假门落地页基址> \
  --app-base <应用侧基址>
```

**实测输出（本次已生成）**：22 名创作者 / 22 条链接（正式 20 + 演示 2），`marketing/out/qr/` 下 svg + png 各 22 个；词表校验 15 条 hard_ban 规则全部通过。

**URL 规则（顺序固定，不得手改）**

| 用途 | 模板 |
|---|---|
| 招募（发给创作者本人） | `{landing}/?utm_source={platform}&utm_medium=creator_recruit&utm_campaign=pro_launch_p1&utm_content={code}&ref={code}` |
| 分享（创作者发给自己观众） | `{app}/s/{video_id}?utm_source={platform}&utm_medium=creator_share&utm_campaign=pro_launch_p1&utm_content={code}&ref={code}&v={variant}` |

示例（`c001` / douyin，占位基址）：

```
https://<landing>/?utm_source=douyin&utm_medium=creator_recruit&utm_campaign=pro_launch_p1&utm_content=c001&ref=c001
https://<app>/s/{video_id}?utm_source=douyin&utm_medium=creator_share&utm_campaign=pro_launch_p1&utm_content=c001&ref=c001&v={variant}
```

**纪律**：
1. 来源参数是 §0.3 #5（来源参数 + 归因落库）与循环边 `v`/`r` 的**唯一取数依据**；换成短链或去参数链接 → 该创作者贡献无法归因。
2. `utm_content`/`ref` 用 `creator_code`，与 `marketing/data/seed_creators.csv` 一一对应；编码规则 `^[a-z0-9]{4,16}$`。
3. 生成器内置 15 条 hard_ban 词表校验：台账文本或链接命中禁用表述 → **拒绝生成**（exit 1）。

**二维码实现与验证（可复核）**

| 项 | 内容 |
|---|---|
| 实现 | `marketing/scripts/qr.py`，纯 Python 标准库（无第三方依赖），字节模式 / 纠错等级 M / 版本 1–40 自适应 |
| 参考比对 | `marketing/tests/test_qr_reference.py` 用独立实现（`api.qrserver.com` 渲染的 PNG）逐格比对：**版本 6/8/13（dim 41/49/69）全部逐格相等** |
| 已知差异（不影响可用性） | 掩码选择：ISO/IEC 18004 允许编码器在 8 个掩码中自选，任一合法掩码解码结果相同。本实现按自己的罚分实现选掩码；实测中版本 13 与参考实现选到同一个掩码，版本 8 不同。**这是编码器自选项，不是缺陷** |
| 离线可用 | 生成链路完全离线；参考比对在无网络/无 PIL 时自动跳过（不 fail） |

### 1.2 统一分享话术模板（零未兑现数字）

三个版本（微信 1v1 / 社群 / 短视频私信）见 `marketing/data/share_scripts.md`。共同纪律：

1. 只能是**机制类表述**（规则先公开、理由可回读、不用注册就能看），**不得出现任何数字，也不得出现任何结果承诺**（含无数字表述）。
2. **不得出现任何竞品对照或比较性贬损**（只能自我陈述，不得以「比别的平台如何」的方式表达）。
3. 不得新增承诺：禁用表述按编号引用（HB-11/12/13/14、HB-16～HB-18、TG-01～TG-06）。
4. 一次只发一跳；同一社群 7 天内 ≤ 2 条。
5. 话术可删减、不可改写；链接不得替换。
6. **哪些句子不可删**（其余宣传句可删）：「不用注册就能看」类（不强制注册的口径锚点 RT-04）、「邀请名额 / 邀请制」类、身份披露句（社群版）。文案内以 `〈不可删〉` 标记。

## 2. 渠道 3 排期｜垂类兴趣社群内容运营

### 2.1 三个相邻垂类（裁定）

| 代号 | 垂类 | 相邻性论证 | 冷启动理由 |

| V-A | `food-home` 家常菜与备餐 | 与 V-B 共享「吃什么/怎么做」的同一决策链 | 供给门槛低、可批量生产、话题化容易 |

时间基准为 T0 相对时间；话题即召回入口（PRD 已实现 `#话题` 正则自动抽标签，创作者无需填表）。

**③ 的启动前置（PRO-19 采纳 PRO-18 O-6）**：③ 依赖 §6.1 的两个回读位（作品页**曝光回读位** / **推荐理由回读位**）实现 —— 未实现前该「展示」无合法取数来源（`community_scripts.md` §1 硬门 1「有真实数据」同理）。因此**不得先按排期启动**，与 §6.1「全部对外物料解锁 T0 的前置」同口径。

### 2.3 外部垂类社群投放清单与创作者身份脚本

### 3.3 样本量与最小可检测差异（**本单的关键发现**）

判据写的是「样本 300–500 访客、差异 ≥ 3pp」。先把 3pp 在 300–500 样本下是否可判定算清楚（`marketing/scripts/power_analysis.py`，两比例 z 检验、双侧 α=0.05、80% 功效、三臂等分）：

| 总访客 | 每臂 | 较弱臂基线 | 检测 3pp 的功效 | 80% 功效下 MDE | 判定 3pp 所需总样本 |
|---|---|---|---|---|---|
| 300 | 100 | 8% | 10.8% | **14.1pp** | 4,497 |
| 500 | 167 | 8% | 15.2% | **10.3pp** | 4,497（Bonferroni 修正 5,445） |
| 3,000 | 1,000 | 8% | 62.9% | 3.7pp | — |
| 4,500 | 1,500 | 8% | 80.0% | 3.0pp | — |

**结论（必须写进看板）**：
1. 300–500 访客时每臂仅 100–167 人，80% 功效下只能检测 **10–14pp** 的差异 → **不足以判定 3pp**。
2. 要判定 3pp，需约 **4,500** 名访客（若做 Bonferroni 修正则约 **5,445**）。
3. 因此本单把 300–500 访客的读数定位为**方向性判据**，正式判定按下表预注册规则执行；**不得**在低功效样本上宣称 3pp 结论。
4. 命名必须分批：9 个候选一批会把每臂压到 33–56 人，MDE 达 **23–31pp**，等于放弃判定能力（与 PRO-8 §4.2 一致）。

### 3.4 预注册判定规则（先写死，后看数）

| 情形 | 判定 | 动作 |
|---|---|---|
| 留资 ≥ 8% 且 V1 − max(V2,V3) ≥ 3pp 且每格 ≥ 100 | 「确定性」为主驱动 | 定位叙事维持 V1 |
| 留资 ≥ 8%，差值 < 3pp | 「确定性」非主驱动 | 定位改为「规则/收益透明」（PRO-8 §3.2 停止条件 ①） |
| 留资 < 8% | 招募叙事不成立 | 停止扩投，回炉文案与渠道 |
| 样本已达 500 而 MDE 仍 > 3pp | **不得宣称 3pp 判定** | 只记方向性结论并标注低功效 |
| 命名子批内差异 < 3pp | 该方向内无显著差异 | 记「无差异」，不得凭偏好选名 |
| **任何情形**（board 裁定 2，PRO-25 轮） | 300–500 访客的读数一律为**方向性结论** | 每次结论**必须标注「低功效 / MDE 10–14pp」**；**不得**在低功效样本上宣称 3pp 判定（见 §14.4） |

## 8. 诚实限定（不得省略）

1. **本单产出的是「可投放物料 + 可计算装置 + 判定规则」，不是实验结果**。所有业务判据当前均为「不可计算」，真实数值必须来自真实访客（§5.2/§5.3）。

3. **300–500 访客不足以判定 3pp**（§3.3）：MDE 为 10–14pp；据此本单不把该样本量的读数当作 3pp 判定。
4. 渠道 3 的排期以 T0 相对时间表示，**不由日历推进**；供给门未达成前不启动规模投放。
5. 承诺卡（t0 相位）未发放，且**不得在 T0 前发放**；发出后 7 天内无法兑现即立即停投。
6. QR 掩码选择为编码器自选项（不影响解码）；本实现未与特定参考实现做掩码对齐，仅做了「同一掩码下逐格相等」的验证。
7. 本单**仍未做**商标/域名初筛、**仍未做**对外部署。人工终审（PRO-12）**已完成**，本轮的返修（PRO-13）就是对该终审判定的处置；但**返修后的物料尚未经过第二轮人工通读**——PRO-12 报告 §7.6 明确要求「物料在此之后被修订，需按新 commit 重新通读受影响文件」，该项已作为新的交接项（§6.3，Editor 增量复审）。
